# v4.1.2 — freestyle, combinations, cushion routes and model score

## Changes

- Recognize the freestyle red/white/black points legend. All detected freestyle discs may be selected; absent team badges alone never imply freestyle. Existing singles/doubles ownership checks remain.
- Compute circular hue averages so red pixels around HSV 0/180 do not average into a false wood colour. The saved freestyle frame now detects all 16 visible coins including red, instead of dropping red.
- Search routes through known opponent-coloured intermediate coins while keeping the final target an own coin. Unknown detections remain obstacles. The simulator rejects nominal striker scratches and opponent pots.
- Add a single cushion rebound of the target coin, alongside existing striker-cushion and one/two-transfer combinations. Include both target-coin legs in the overlay.
- Admit sharper candidate cuts (about 69 degrees) before full nominal physics verification; never display solely because the geometric candidate exists.
- Show model robustness: nine simulations vary launch speed ±10%, aim ±0.35 degrees and wall restitution 0.87/0.93 around the assumed 0.90. The percentage counts successful model trials, **not actual-game pot probability**. At least 7/9 gives green final guidance; lower counts use orange. Intermediate coins use orange and striker approach uses cyan.
- Show Steady after three consecutive near-stationary frames; show Adjusting on movement. Preserve manual selection across up to three missed striker frames without drawing stale lines. Sustained missing detection clears it. Show the selected coin even when no verified route is available.
- Keep yellow patterned team coins out of the star/decoration rejection path. Match the visible local badge even when an emote obscures the opponent; unknown-colour discs remain obstacles. Require stronger coloured-area support for score badges so the emote does not become a false orange badge.
- Recognize a packed opening (at least twelve detected discs near the centre) and distinguish “Opening cluster — no verified pot yet” / waiting for team colour from missing board capture.
- Replace the absolute-sounding “No clear shot” with “No verified route found” guidance. The search is bounded and cannot prove that a position has no playable shot.

## Validation and limits

Full saved-screen regressions, singles blue/teal ownership, doubles white ownership, freestyle selection and missing-legend rejection, yellow skins, emote rejection, opening-cluster recognition, mixed-colour transfer refresh, unknown-obstacle rejection, striker/coin cushion reflection, opponent-pot rejection, actual model score bounds, steady/moving state, route cycling and gesture release tests pass. View tests use JVM Android stubs and do not prove real WindowManager input delivery. TypeScript passes.

No gameplay inputs were sent. Local replay is conditional on assumed friction, coin sizes, rails, restitution and power. Live calibration, actual outcomes, sustained phone performance and the full three-match checklist remain outstanding. More than one cushion and cushion-plus-combination routes are not implemented. No 100% accuracy claim is warranted.

These changes were built and linted successfully, then included in v4.2 with the stability and optional gesture controls. See V4.2_REPORT.md for the final artifact and validation. The installed app remains v4.1.1 while the user tests; this development APK was not automatically installed during their game.
